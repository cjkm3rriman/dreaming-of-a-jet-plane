# Static audio build pipeline

How every pre-recorded clip in the app is made, changed, and shipped. This
replaced the iMovie workflow on 2026-10-03, when all 12 deliverables (24 S3
objects) were first deployed from here. In a Claude Code session, invoke
`/build-audio` — the skill walks the same process with the approval gates
built in.

## The one-sentence model

`static_audio.json` is the **source of truth** for every script, sound, and
mix decision; `scripts/build_static_audio.py` renders it; the S3 audio is a
build artifact. Change the manifest, render, audition, upload.

## Everyday loop

```bash
# 1. Edit audio_build/static_audio.json (a script line, a gain, a gap)
# 2. Render (TTS keys come from the Railway env)
railway run uv run python scripts/build_static_audio.py --entry scanning-again --voice ronald
# 3. Audition audio_build/out/ronald/scanning-again.{mp3,opus} (gitignored)
# 4. Ship the EXACT take you auditioned:
railway run uv run python scripts/build_static_audio.py --entry scanning-again --voice ronald --upload-only
```

**`--upload-only` is the only correct way to ship.** TTS reads differ on
every render, so plain `--upload` (render-then-push) would deploy a take
nobody auditioned. Back up the live files first (`aws s3 cp` the keys —
see the dated folders on the Desktop for prior art); players client-cache
clips up to 1h, so changes roll out within the hour.

## Manifest anatomy

One entry per deliverable. Timeline steps run in order:

| Step | Meaning | Options |
|---|---|---|
| `{"tts": "..."}` | Narrator speech | `prompt` (steering tag), `speed` (pitch-preserving atempo), `gain_db`, `overlap_ms` (start under the previous audio's tail) |
| `{"robot_tts": "..."}` | Scanner-robot speech — always ElevenLabs voice `weA4Q36twV5kwSaTEL0Q`, regardless of narrator | `gain_db` |
| `{"sfx": "file.mp3"}` | A file from `assets/sfx/` | `trim_ms`, `gain_db`, `fade_out_ms`, `overlay` (list of `{sfx, at_ms, gain_db}` laid over it) |
| `{"silence_ms": N}` | A gap | |

Entry-level options: `bed` (an SFX looped under the whole timeline:
`start_ms`, `fade_in_ms`, `gain_db`, `fade_out_ms`, `end_before_ms` — fades
are bed-only, the voice never dips), and `upload_prefix` + `s3_name` for the
free tier (see below). Everything masters to the app's `TARGET_DBFS` (−20)
and exports stereo through `free_pool.export_audio_segment` — the same
constants as generated plane audio, so statics and dynamic tracks never
mismatch in loudness, channels, or codec params.

## Voices, names, and models

- **The narrator's name is bound to the voice**: scripts say `{narrator}`,
  and the manifest's `narrators` map resolves it — **Hugo = Inworld
  (`ronald`), Hamish = ElevenLabs (`edward`)**. The holiday lore in old
  scripts was a voice migration. An unmapped voice fails loudly.
- **Models are code-pinned for statics**, independent of the Railway env
  vars that steer dynamic tracks: `STATIC_INWORLD_MODEL` (inworld-tts-2) and
  `STATIC_ELEVENLABS_MODEL` (eleven_v4) in the build script. The renderer
  prints both against the live env at every run.
- **Steering** (`prompt`) is an Inworld inline instruction tag; only
  non-flash tts-2 obeys it — dropped with a note everywhere else.
- **Non-verbals** (`[chuckle]`, `[laugh]`, `[gasp]`) are written inline in
  the script text where the moment happens. Inworld tts-2 (both) renders
  them natively; eleven_v4/v3 gets them translated to ElevenLabs vocabulary
  (`INWORLD_TO_ELEVENLABS_TAGS`); any other model gets them stripped so
  brackets are never spoken. Use sparingly — these clips repeat daily; the
  high-frequency rescan clips deliberately carry none.

## Sound language

Deep-scans and the robot belong to the **paid** tier (it scans); the free
tier **tunes in** — radio static and dials, no robot, no deep-scans. The
jazz lounge bed is the sign-off signature on both overandouts.

## Free tier: one voice, coupled to the dynamic provider

Free deliverables (`upload_prefix: free` / `free/intros`) are single
voice-independent files. The six intros are stitched onto free-pool plane
bodies **generated by the production `TTS_PROVIDER`**, so the whole free set
must be that provider's voice. **If the dynamic provider ever changes,
re-render and re-upload the free set in the new voice** (`--voice edward
… --upload-only` after audition — the narrator binding fixes the name
automatically). Skipping this gives free listeners a narrator change
mid-track on every pooled plane.

## QA / audition

Renders go to `audio_build/out/{voice}/` for local listening. For a proper
review, publish an A/B page (new render vs the live S3 file) as a Claude
artifact — see the "Static Audio Audition" artifact from the 2026-10
rebuild for the pattern. Compare against the **.opus** production files:
they are the masters the players fetch (`--upload-only` writes both formats
from one master, keeping the mp3 twins honest). Useful checks: pydub
duration/dBFS/channels, and a Whisper transcription to confirm steering
tags were performed, not spoken.

## History / provenance

The original clips were hand-made in iMovie; their scripts and SFX
structures were recovered in Oct 2026 by silence-envelope segmentation plus
faster-whisper transcription of the production files, then refined by ear
(Callum) over ~20 audition rounds. `assets/sfx/` holds the SFX sources
exported from the iMovie era (DOJP-36); the robot-*.mp3 files there are
recordings of the same robot voice the pipeline now generates fresh.
